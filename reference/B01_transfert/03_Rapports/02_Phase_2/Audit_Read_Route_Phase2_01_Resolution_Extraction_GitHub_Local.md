## Passage C — usage réel sous contrainte

**Agent ou designer cherchant uniquement une route :** le CLI est l'entrée rapide recommandée dans QUICKSTART et les README. Dans l'état B01, `DIRECTION/START`, `ACTION/RUN-LITE` et les 22 autres locators principaux ouvrent des blocs cohérents. Si le code prend un titre imprimé dans un exemple pour le titre réel, l'en-tête de sortie reste crédible tandis que l'instruction réellement lue est factice ou tronquée. Le lecteur doit conserver la distinction entre extrait de route et source normative complète ; le validateur de package ne mesure ni la qualité de la décision ni celle de l'artefact.

**Intégrateur ou mainteneur :** `validate_all.py` lance un seul cas positif `DIRECTION/START` et un seul cas négatif `DIRECTION/UNKNOWN`, vérifie leur code de sortie, puis construit et valide deux distributions. Il ne compare ni le corps attendu, ni le propriétaire du locator, ni les 24 corps ; d'où les trois PASS complets lors des modifications de titres dans la source. Le build Local compense spécifiquement un chemin de README racine incompatible ; `official/README.md` existe dans les deux variantes et montre que cette compensation ne couvre pas tous les mauvais owners. La recherche du premier titre et la découpe du bloc appartiennent au lecteur ; l'unicité de la table est déjà F-VRM-001 côté validateur.

**Reviewer :** les messages « locator inconnu », « propriétaire absent », « titre introuvable » et l'aide d'argument sont des frontières identifiables. Un résultat code 0 avec un corps incorrect est plus trompeur qu'un rejet contrôlé. Une ligne commençant par `#` dans un bloc de code est du texte d'exemple, pas une nouvelle section Markdown ; un titre avec deux espaces devant reste un titre Markdown. Les exemples de mutation isolent donc un écart de lecture de structure, et pas seulement une divergence de style éditorial.

## Passage D — constat, déduplication et suite

### F-RRT-001 — extraction des sections sans reconnaissance de Markdown

**Preuve :** `read_block` lignes 43–58 prend la **première** ligne égale au titre demandé, puis arrête la sortie sur toute ligne brute commençant par `#` avec un niveau compatible. Les copies avec un faux titre dans un bloc de code, un `###` de code dans une section ou un titre suivant indenté rendent chacune **code 0 / PASS complet** alors que le bloc affiché est respectivement factice, incomplet ou élargi à la route voisine. **Impact plausible :** un agent lit une instruction manquante ou étrangère avec un en-tête CLI crédible ; l'effet sur une décision réelle n'a pas été mesuré. **Owner pressenti :** logique de recherche et de découpe de `read_route.py`, plus tests d'intégration limités au code de sortie ; les propriétaires des règles ne devraient pas être changés pour contourner le lecteur. **Test discriminant de résolution :** préserver 24/24 routes B01 et la présentation GitHub/Local ; vérifier la valeur du corps sur des sources comportant un titre imprimé dans un bloc de code, un `#` de code au milieu du bloc et un vrai titre indenté de deux espaces. Un doublon réel de titre Markdown doit être signalé de façon explicite plutôt que choisi arbitrairement. Gravité finale laissée à la phase 10.

**Non-fusions provisoires :** F-VRM-001 protège les clés, owners et destinations **dans la carte**, même lorsque les fichiers propriétaires sont inchangés ; F-RRT-001 concerne l'extraction incorrecte **dans un propriétaire correctement indiqué**. F-DIR-028 est l'impossibilité déjà constatée d'appeler par la CLI des titres cités hors table. F-ALL-001 est l'oracle trop faible de la suite supérieure ; F-RRT-001 fournit le mécanisme de contenu et les trois mutants discriminants. Le README officiel faussement assigné confirme F-VRM-001, sans nouvel ID. Les éventuelles fusions finales resteront à décider après les phases transversales.
