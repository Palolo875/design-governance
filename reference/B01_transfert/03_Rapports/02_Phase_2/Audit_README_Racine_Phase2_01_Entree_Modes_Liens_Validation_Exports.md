## Passage D — F-RDR-001, frontières et prochain bloc

### F-RDR-001 — `ITER` présenté par le déclencheur « amélioration guidée par observation »

**Preuve textuelle :** `README.md` 41–51, surtout 46 ; `DIRECTION.md` 127–140/672–674 ; `ACTION.md` 349–356 ; QUICKSTART 130–144/151. **Écart :** la table de départ ne nomme pas la condition qui distingue `ITER` d'une correction sur une direction absente ou non retrouvable. **Effet possible :** classer `ITER` par provenance de la demande et sauter le rétablissement de la direction, le rappel du scope et l'épreuve de non-régression. **Atténuations :** 39 confie sans ambiguïté la classification à START, 51/53 bornent la table comme point d'entrée non normatif ; QUICKSTART 132 donne la condition absente ici. **Test discriminant ultérieur :** même observation sur (a) surface existante avec direction retrouvable, (b) direction perdue, (c) écran nouveau sans direction identitaire et (d) règle partagée ; donner la seule table puis le texte complet, et comparer mode, source chargée, risque, preuve et action. **Owner provisoire :** ligne de façade du README racine ; aucune règle de mode nouvelle, aucune gravité finale ni patch décidé.

**Déduplication :** F-QS-002 concerne le classement `DIRECTION` par craft dominant dans une autre façade ; la ligne README 48 en est une occurrence voisine, sans nouvel ID. F-RDR-001 concerne précisément **le prérequis perdu d'ITER**. F-QS-001 et F-DIR-009 concernent les étapes créatives ou retouches artificielles ; F-SK-002 les chemins de la skill selon export ; F-MAN-002 l'invariant de version ; F-BLD-001 à 004 l'assemblage et la reprise des distributions ; F-VRC-004/005 la vérification stricte ; F-ALL-001 l'oracle négatif. Leur recoupement avec le README ne les résout ni ne crée de copies d'IDs.

**Registre : 156 avant, 157 fiches provisoires après F-RDR-001.** Les liens de ce README, son ancre et la route initiale fonctionnent dans leur scope ; les réserves de preuve et l'autorité des cinq propriétaires sont explicites.
